# Releasing

AVID Core is a source-only library. GitHub Releases are the canonical direct release record. A stable release uses a cryptographically signed `vMAJOR.MINOR.PATCH` tag from Thomas Lothian matching the `Cargo.toml` version. The tag is the release authorization. No portable Windows ZIP, installer, application binary, FFmpeg runtime or SignPath signing is required here.

Before tagging, run the checks in [TESTING.md](TESTING.md), verify `cargo package --locked` contents, update [CHANGELOG.md](../CHANGELOG.md), refresh [dependency-inventory.json](dependency-inventory.json), and review [licensing](../LICENSING_REVIEW.md). Set repository variables `RELEASE_GPG_PUBLIC_KEY` (Thomas's armored public key) and `RELEASE_GPG_FINGERPRINT` (its 40-character fingerprint) before the first stable tag; absent or mismatched variables block publication. The [source release workflow](../.github/workflows/source-release.yml) verifies the tag signature and Cargo version, then tests and packages the source crate, CycloneDX SBOM, SHA-256 checksums, and GitHub artifact attestation. Release notes should describe highlights, changes, fixes, known issues and consumer migration information, omitting empty sections. Each host qualifies its own platform packages independently.

Prerelease tags such as `v0.4.0-beta.1` are not production signed. Development builds originate from `main`, are labeled unsupported, and any retained CI artifact expires after 30 days. Exact release automation and signing-key configuration are described in [CODE_SIGNING_POLICY.md](../CODE_SIGNING_POLICY.md).
